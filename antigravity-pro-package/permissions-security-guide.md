# دليل الصلاحيات والأمان (مبني حرفيًا على `/docs/permissions`, `/docs/agent-settings`, `/docs/sandbox`)

## 1. جدول أنظمة الصلاحيات الجاهزة (Presets)

| الإعداد | الـSandbox | الأوامر الطرفية | متى تستخدمه |
|---|---|---|---|
| **Request Review** | معطّل | كل أمر يحتاج موافقتك | مهام حساسة جدًا تريد مراقبة كل خطوة فيها |
| **Default** (الافتراضي) | مفعّل | تعمل بحرية داخل الـsandbox، تطلب إذنًا خارجه | **الاستخدام اليومي الموصى به لمشروعك** |
| **Auto** | مفعّل | تعمل بحرية داخل الـsandbox + تقييم تلقائي ذكي للأوامر خارجه (آمن/قابل للتراجع يمر، الخطير يتوقف) | عندما تثق بالوكيل لكن تريد حماية تلقائية ذكية |
| **Turbo** | **معطّل بالكامل** | كل شيء بدون قيود، وصول كامل للملفات | **فقط** لمهمة محددة تحتاج صلاحية كاملة مؤقتًا — أعده إلى Default بعدها |

**كيف تُغيّر الإعداد:**
- لكل مشاريعك: **Settings → General → Global Permissions → Permission Preset**.
- لمشروع واحد فقط: **Settings → Projects** (الافتراضي: يتبع الإعداد العام).
- من صندوق الرسائل مباشرة (v2.23.0+): أيقونة الصلاحيات بجانب حقل الكتابة.

## 2. الـTerminal Sandbox — حالة جهازك (Windows 11, تحديث 24H2+)
جهازك يدعم العزل الكامل الحديث: الأوامر داخل الـsandbox يمكنها الكتابة في
مجلدات مشروعك والمجلدات المؤقتة فقط، ولا ترى أي شيء غير مصرَّح به صراحة
(مثل `~/.ssh` أو `.env`)، والشبكة مقفلة إلا للنطاقات التي توافق عليها.
هذا أفضل من السلوك القديم على Windows (حيث كانت المجلدات خارج ملفك
الشخصي قابلة للقراءة فقط بدون كتابة) — لذا لا داعي لتفعيل Turbo كحل
افتراضي لمجرد تفادي قيود كانت موجودة في نسخ أقدم.

## 3. قواعد Allow/Deny/Ask يدوية (تتفوق دائمًا على الـPreset)
مثال لإتاحة أمر محدد دون طلب إذن في كل مرة:
```
command(git push)
command(regex:docker compose .*)
```
أنواع الإجراءات القابلة للتحكم: `read_file`, `write_file`, `read_url`,
`execute_url`, `download_url`, `command`, `mcp`. الترتيب دائمًا:
**Deny > Ask > Allow** (القاعدة اليدوية تتجاوز الـPreset العام).

## 4. ماذا تفعل عند الرفض (Ask/Deny)؟
- إذا طلب الوكيل إذنًا ورفضتَه: اشرح له *لماذا* رفضت بدل الرفض الصامت —
  هذا يساعده على عدم تكرار نفس الطلب بصيغة مختلفة.
- إذا تكرر نفس طلب الإذن كثيرًا لعملية تثق بها: أضفها كقاعدة `command`
  صريحة في Allow بدل تبديل الـPreset بالكامل إلى Turbo.
- لا تستخدم `--dangerously-skip-permissions` (في الـCLI) إلا لمهمة واحدة
  مؤقتة تفهم عواقبها بالكامل.

## 5. وصول الوكيل خارج مساحة العمل
افتراضيًا، الوكيل يرى فقط مجلدات مشروعك + `~/.gemini/antigravity/`
(مكان القطع الأثرية الداخلية). تفعيل "Agent non-workspace file access"
يوسّع هذا — فعّله بحذر فقط عند الحاجة الفعلية.
